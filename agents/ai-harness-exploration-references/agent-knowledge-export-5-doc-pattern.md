# 5 文档导出模式 (Agent Knowledge Export)

> **适用**: 完成 ai-harness-exploration 5 步后, 把累积经验转成可喂给其他 Agent 的标准化 MD 集合.
> **首例**: 2026-06-03 Hindsight 5 文档 (61 KB, 1719 行, 7 文件, `~/hermes-all/exports/hindsight-agent-brief/`).
> **目标**: 其他 Agent 读 7 文件 8-25 分钟, 跳读 5 分钟拿到决策.

## 7 文件结构 (固定)

```
exports/<topic>-agent-brief/
├── 00-README.md              # 入口 + 决策树 + TL;DR (5-30 秒版)
├── 01-deploy-guide.md        # 怎么装 (3 路径, 步骤, 验证, 卸载)
├── 02-handoff-api.md         # 怎么调 (API + 5 重防死循环, 适用: 有 manual API 的工具)
├── 03-case-study-N-stages.md # 前车之鉴 (推销→失控→反思→卸载→重装 5 阶段)
├── 04-architecture.md        # 在系统哪一层 (适用: 工具/库/框架)
├── 05-decision-matrix.md     # 装不装 (8 问清单 + ROI 3 场景)
└── 99-references.md          # 来源汇总 (官方+本地+实测)
```

## 每文件模板

### 00-README.md (入口)

**必备 7 节**:
1. **5 文档地图** (表格: # / 文件 / 受众 / 关键问题)
2. **决策树** (5 秒决定读哪些, 5-7 个分支)
3. **TL;DR** (30 秒版: 装不装? 怎么装? 怎么调? 必须避的坑)
4. **关键真相** (5-10 个"你可能不知道"的颠覆性发现)
5. **验证清单** (Agent 装好后跑这些)
6. **风险表** (装之前必读, 等级 + 缓解)
7. **退出成本** (装之前想好)

### 01-deploy-guide.md (装)

**3 路径对比表** (推荐度 + 适用 + 命令).

**每路径 5 步**:
- Step 1: 前置检查
- Step 2: 启动
- Step 3: 验证
- Step 4: 配 Hermes / 集成
- Step 5: 端到端实测

**5 个常见错误** (debug 指南: 错误 / 表现 / 修复) + **卸载** (退出成本, 完整步骤, 保留 .bak).

### 02-handoff-api.md (调)

**何时用 / 何时不用** (关键决策).

**5 重防死循环机制** (适用: 有 API 的工具):
1. 人工触发 (不靠 cron/hook)
2. 限频 (MAX=N/天)
3. sha256 去重
4. 长度校验
5. 幂等 (state 持久化)

**核心 API + CLI 备选 + 状态文件 + 集成到 Agent turn 流程 + 关键陷阱**.

### 03-case-study-N-stages.md (前车之鉴)

**5 阶段 (推销→失控→反思→卸载→重装)**:
- 阶段 1: 推销过快 (红旗语言: 业界共识/最佳实践/必需)
- 阶段 2: 主动化失控 (敷衍信号: 已重启/好/行)
- 阶段 3: 第一次反思 ("评估一下" = 反弹信号)
- 阶段 4: 彻底卸载 (保留 .bak = 用户友好)
- 阶段 5: 重新探勘 + 实装 (上手才知道真价值)

**8 问清单 (装之前必答)** + **关键心法 (8 条)**.

### 04-architecture.md (在哪一层)

**总览图 (ASCII) + 4 层职责对比表 + 关键真相 + Token 成本 + 协作流 + 5 件套工具状态 + 替代方案对比**.

### 05-decision-matrix.md (装不装)

**TL;DR 表** (你的情况 → 建议) + **5 决策维度**:
1. 痛点真实吗
2. 边际价值多少
3. 真实成本 (装 + 月 × 12 + 退出)
4. 退出成本
5. 长期风险

**ROI 计算 (3 场景)**: 普通 / 痛点严重 / 5+ Agent 共享.

**8 问清单** + **3 装必做 + 3 装了不该用 + 不装的替代方案 + 决策模板 (直接抄)**.

### 99-references.md (来源)

**官方文档表** (URL + 用于哪个文件) + **本地资源表** (路径 + 用途) + **探索与对比来源** + **实测数据表** + **Wiki 历史** + **关键发现时间线** + **引用本文档 (citation 格式)**.

## 关键约束 (从 Hindsight 案例提炼)

### 1. 写之前必读 5 个 references

- 官方文档 (官方视角, 避免"业界共识"陷阱)
- case study (5 阶段翻车记录, 避免重蹈)
- corrections (颠覆性发现, 修正之前错误)
- 3 个 skills (实操 API)
- 3 个 scripts (实际代码)

### 2. 7 文件大小分布 (Hindsight 实测)

|---|---|---|
| 00-README | 134 | 8% |

## 失败模式 (避免)

1. ❌ **只写 1-2 文件** — 决策树缺, 其他 agent 找不到入口
2. ❌ **复制 wiki 内容** — wiki 是给人读的, 5 文档是给 agent 读的, 视角不同
3. ❌ **推销式语气** — "业界共识/最佳实践" → 立即改诚实评估
4. ❌ **不写 99-references** — 其他 agent 无法验证, 信任低
5. ❌ **跳过 case study** — 前车之鉴缺, 重蹈覆辙风险高
6. ❌ **5 文档导出时不更新 wiki** — 双轨不同步, 用户/Agent 困惑

## 适用范围

✅ **适用** (工具/库/框架有累积经验后):
- 复杂工具 (3+ 部署路径)
- 有 manual API 需 5 重防死循环
- 翻车过 (5 阶段案例)
- 跨多层架构

❌ **不适用** (单一概念/小工具):
- 简单脚本
- 单 API 工具
- 没用过的库
